# CloudLaunch in the optional DevOps ecosystem

CloudLaunch owns builds, release identifiers and deployment events; Platform owns Kubernetes/GitOps visualization; Triage owns reusable analysis/contracts; Ops Pilot owns incident orchestration/approvals; Labs owns controlled failure injection. No component is started automatically and no integration grants production access.

The existing pharmacy application, PostgreSQL volume, RBAC, health policy and pipeline remain independent. Jenkins now tags a built image with its immutable Git SHA, records started/healthy/failed and observed rollback verification outcomes, and optionally scans source and built image with Trivy when CLOUDLAUNCH_TRIVY=1. An enabled scanner must already be installed. No scanner result is fabricated when disabled. The existing automatic rollback behavior is preserved; it is not a new Ops Pilot policy or authorization. Do not deploy this pipeline to customer infrastructure without its existing approval requirements.

Install `requirements-ecosystem.txt` explicitly on the build agent only when using the integration. The exact Triage package pin provides the common contract/client; runtime application requirements are unchanged. Set OPS_PILOT_EVENT_URL to a loopback HTTP or HTTPS `/webhooks/ecosystem` URL, OPS_PILOT_SERVICE to the registered service ID, and OPS_PILOT_EVENT_TOKEN through protected Jenkins credentials/environment. The receiver's matching OPS_PILOT_EVENTS_CLOUDLAUNCH is source-scoped and cannot approve repairs. Never paste credentials into a pipeline or log.

`python scripts/report-release.py healthy --state-dir /private/cloudlaunch-events` writes a private audit record/constant-cardinality Prometheus textfile and optionally sends one deployment event. Use it only after an actual health pass; it performs no deployment. The script exits with an integration error and retains its private outbox if delivery fails. Jenkins treats reporting separately from deployment; a reporting warning is not proof of delivery. Inspect the outbox and resend its original event using the shared CLI, keeping the id unchanged. Configure an existing node-exporter textfile collector to read the private release.prom through an appropriately limited mount; do not expose the audit/outbox. Build/deployment elapsed seconds and status do not establish application correctness.

`python scripts/deploy-ecosystem-demo.py --allow-disposable-host` builds/runs the existing sample site with a unique ownership label, immutable image ID, loopback ephemeral port, 64 MiB memory, 0.25 CPU, read-only filesystem and dropped capabilities. This is an explicitly owned test-host action, not a production deploy. Its cleanup function refuses a mismatched ownership label. The Labs acceptance driver uses this function, actual monitoring and Ops Pilot's original approved restart. The sample is not the stateful pharmacy application. See Ops Pilot `docs/ECOSYSTEM.md` for the full topology, exact cross-repository refs and current acceptance evidence.

Local verification: `python -m unittest discover -s tests -p test_ecosystem_reporting.py -v` checks private reporting and refusal semantics without deploying; `python -m compileall -q scripts` checks syntax. Real Docker/monitoring/recovery acceptance runs only on disposable CI. Jenkins server authentication, actual pipeline execution, Trivy vulnerability DB/scanning, customer access and the whole-stack 8 GB footprint require separate measured acceptance. Prometheus is Apache-2.0, Grafana AGPL-3.0, K8sGPT Apache-2.0; no external server source is copied into this repo.
